Try the approved behavior

1. Move Delivery. Undo restores its boundary and all members. 2. Move it again, then use Simulate external member move. Undo is blocked with a reason. 3. Create a frame around unassigned cards. Hidden cards are included; existing members are not taken. 4. Resize or delete a frame: neither moves cards.

Proposed controls: drag a frame title to move its group, drag its corner to resize only the boundary, or use numeric fields and buttons. Drag cards independently without changing membership. Escape cancels a gesture, creation, or pending simulated save. Canvas scrollbars pan the view; Fit includes frame geometry.

Mockup limits and approval scope

This standalone prototype demonstrates interactions, not production persistence, SSE, relationship editing, or concurrency guarantees. Saves use a short timer and an optional failure. Histories remain per board during tab use. Reload resets sample geometry as well as history, unlike the planned application which will persist board geometry. Automatic positions use fixed fixture coordinates. No history is shared across tabs.

Review control placement, initial-capture feedback, member visibility, grouped movement, and blocked-history explanations. Exact hit testing and history capacity still belong to implementation planning. This artifact follows docs/frame-specification-v1.md; it does not change the approved readability mockup.
