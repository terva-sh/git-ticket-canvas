Walk through one pen and one ordinary frame

  1. Select DEMO-A. Add it to Release work without changing its position or automatic mode.
  2. Toggle its frontend label. It moves to Inbox but remains a frame member outside the boundary.
  3. Move the frame. All members, even outside or filtered cards, move and become manual.
  4. Toggle the label again. The manual card stays put. Return it to automatic placement to route to Frontend while retaining membership.
  5. Reset, add A to the frame, then move the frame and undo. Automatic placement returns using current labels. Repeat with an external member move to see a blocked undo.
  6. Hide done. The pen count and overflow do not shrink. Preview removal or resizing, then Cancel. Apply with failure enabled to see rollback. Close the panel during a save to see pending feedback remain.
Mockup limits and review scope

This is a control and state walkthrough of the approved pen policies. It uses fixed-size synthetic cards, a fixture slot search, one board, and a 900 ms simulated save. It does not select a production placement algorithm or persistence schema. Refresh resets everything. Label changes simulate accepted ticket updates, not a spatial label-editing action.

Review the distinct pen/frame appearance, outside membership, destination counts, overflow, manual overrides, removal, previews, pending feedback, and keyboard controls. There is no drag, zoom, SSE, board switching, creation, Arrange, or multi-rule editor here. Frame history demonstrates one grouped move and conflict blocking, not the full production frame editor. Production race, persistence, and responsiveness tests remain future work. Creating this mockup does not approve it or promote the draft ticket.
